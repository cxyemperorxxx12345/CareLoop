# 愈见 CareLoop · 优化与新增功能提案（2026-10-13）

> 角色：顾问/总设计师。以下每条都基于**实际代码/线上库状态核实**，不是拍脑袋。
> 请逐条裁定：通过 / 不做 / 改方案。通过后我再派人实现。
> 排序原则：先看「演示当天能不能站住」，再看「是不是真的更人性化」，最后才是锦上添花。

---

## A 级：强烈建议做（演示价值 + 人性化，缺口真实存在）

### A1. 让核心卖点「对照他自己」在演示当天真的出现 ★最高优先
- **现状**：机制①个人基线的展示层依赖 `daily_baseline` 表；演示库停在迁移 00011，表不存在，`getBaselines()` 返回 `[]`，所有基线区块静默不渲染。
- **问题**：我们对外讲的主打主张（"每个患者唯一的对照是他自己"）在演示时**一个字都看不到**，等于卖点自我阉割。
- **方案**：前端加一层**本地兜底计算**——`checkins` 表有真实数据且三端可读，用它现算近 7 天中位数 + MAD 偏离带（数学与迁移 00019 一致），`daily_baseline` 有数据时优先用表，没有就用现算值。
- **成本**：纯前端，无迁移、无部署；约 1 个 lib 函数 + 3 处展示接入。
- **风险**：低。现算值只用于展示，不写库；样本 <3 天时明确标注"样本不足，暂用通用参考值"，不许装作有基线。

### A2. 补上闭环最后一跳：医护处理预警后，患者必须收到回执 ★最高优先
- **现状**：`clinicianApi.resolveAlert()` 只把 alert 置为 resolved 并记处置措施/结论，**不给患者任何回执**。
- **问题**：患者上报"伤口不行"→ 医护在后台处理完 → 患者端毫无变化。这是"全周期闭环"叙事里最致命的一处断点，也是最伤真实体验的地方（老人会以为没人管他）。
- **方案**：医护点"处理"时，同时写一条 `messages`（RLS 允许医护 INSERT messages，技术上完全可行）：「王医生已查看您的上报：{处置措施}。{处置结论}」+ 深链回对应页面；未读置顶。患者端消息中心即可见。
- **成本**：纯前端 + 一条 insert，无迁移。
- **风险**：低。需注意避免重复点击产生重复消息（加处理态与幂等判断）。

### A3. 医护端新增「照护时间轴」总览页签
- **现状**：360 详情分 档案/用药/随访/体征/事件 五页签，checkins、alerts、followups、messages 分散在各处。
- **问题**：答辩讲"闭环"时要靠嘴把五页串起来；医护日常也看不到"这个人这段时间到底发生了什么"。
- **方案**：新增一个时间轴页签，把体征、预警、家属响应、处置结论、随访完成按时间合并成一条故事线（出院 → 每日 → 异常 → 干预 → 转归），异常节点高亮。
- **成本**：中。数据都已在 `patientDetail()` 里取到，主要是聚合 + 渲染。
- **风险**：中低。要做性能与空态处理；建议放在第一个页签。

### A4. 打卡页减负：按病种给"今天该测什么"
- **现状**：7 个输入框平铺（体温/收缩压/舒张压/心率/血糖/体重/疼痛评分），字段可留空但对老人是认知负担。
- **方案**：按患者病种/医嘱算出"今日建议测量项"置顶并默认展开（如高血压：血压+心率；糖尿病：血糖），其余折叠进"更多（可选）"；加"沿用昨日数值"一键填充；提交后给一句人话反馈（"今天血压比你自己 usual 略高，已记录"）。
- **成本**：中低。纯前端；"今日建议项"可先用诊断关键词做规则，不必上模型。

## C 级：可选 / 有风险，需你拍板

- **C1 助手断网兜底**：MiniMax 不可用时退化为本地知识库（`knowledge_docs`）关键词检索，避免演示现场断网时助手变哑巴。要做"降级时明确说明是本地检索"，不许装成 AI 回答。
- **C2 消息按紧急度排序 + 未读置顶**：老人分不清轻重。

## 必须提请注意的两个「宣称与实际不一致」风险

1. **分诊规则**：机制①的双通道判定写在 `triage-symptom` Edge Function 里，**该函数尚未重新部署**。演示时若现场跑症状自查，线上跑的仍是旧规则——一旦被追问"为什么这条判黄不判红"，答案会与我们的说明对不上。要么上线前务必重部署，要么现场演示时只展示已存的历史结果。
2. **一键同步**：迁移 00020 未应用前，患者点同步走的是**降级通道**（写入症状档案，医护端 360「事件 → 症状自评」可见），不是真正的医护端预警。演示话术要如实，别声称"已进预警中心"。
