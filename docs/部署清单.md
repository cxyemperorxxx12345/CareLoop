# 部署清单（Supabase 后台操作）

> 本项目前后端直连托管 Supabase，**改 `supabase/` 下的任何东西都必须按本清单落地才生效**。
> 后台地址：Miaoda 应用后台 → Supabase（项目 `supabase367321646417096704`）。
> 当前待办区见文末；完成一项划掉一项。

---

## A. 应用 SQL 迁移（SQL Editor）

1. 后台进入 SQL Editor，新建查询
2. 按序号粘贴待应用迁移的**全文**（如 `supabase/migrations/00017_t1_escalate_no_red.sql`），Run
3. 验证（任选）：
   - 00017：`SELECT id, level, family_action FROM alerts WHERE source='medication' AND family_action='escalate';` —— 应全部为 `yellow`
   - 00018：用登录页一键填入演示账号登录，能进即口令对齐成功
4. 迁移均幂等，重复执行无副作用；**执行完在文末待办区登记**

> 全新库一次性重建：直接粘贴 `supabase/ops/full_schema_0001_0020.sql` 全文（含 00001–00020 全部迁移），Run 一次即可。

## B. 部署 Edge Function

1. 后台进入 Edge Functions → 选择函数（如 `reminder-scan`）
2. 用 `supabase/functions/<函数名>/index.ts` 的**全文**替换线上代码（`_shared/` 下的文件如同时改动也要一并同步）
3. Deploy，等状态变为 Active
4. 验证：
   - `reminder-scan`：患者端到点不打卡，30 分钟后消息中心应出现升级消息；同时段两种药只出现**一条**列出全部药名的提醒
   - `triage-symptom`：症状自查输入「胸口有点闷」严重度 2 → 黄色；「胸痛」严重度 7 → 红色
5. **部署完在文末待办区登记**

> 函数所需密钥：`SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` / `SUPABASE_ANON_KEY`（平台自动注入）；`INTEGRATIONS_API_KEY`（MiniMax，Functions → Secrets 手工配置，重建项目时容易漏）。

## C. pg_cron 注册（仅全新库需要）

迁移 00004 已含 `careloop-reminder-scan` 定时任务注册，依赖 vault 中的 `project_url` / `publishable_key` secret。全新库应用 full_schema 后确认：`SELECT * FROM cron.job;` 有一条每分钟任务。

---

## D. 最终上线 Miaoda 的一天（一次性执行顺序）

> 前提：日常开发全部在本机跑（`corepack pnpm dev`，localhost:5173），后端仍是旧库。
> 前端对未部署的能力都做了兜底（打卡走客户端日粒度、同步降级到症状档案、无基线时不显示基线区块），
> 所以**上线前演示也不会报错**。以下动作只在最后一次性执行。

1. **SQL 迁移**（SQL Editor，按顺序，全部幂等）
   - 先补齐 `00012 ~ 00016`（旧库缺这五个，逐个粘贴 Run）
   - 再跑一次 `supabase/ops/PENDING_apply_now.sql`（00017 + 00018 + 00019 + 00020 合并包）
   - 验证：`SELECT count(*) FROM cron.job;` 有任务；`SELECT 1 FROM pg_proc WHERE proname='patient_escalate_alert';` 有结果；
     `SELECT count(*) FROM daily_baseline;` 有演示基线数据
2. **Edge Functions 重新部署**：`triage-symptom`（分诊新规则 + 个人基线双通道）、`reminder-scan`（同时段多药合并提醒）。
   确认 Secret `INTEGRATIONS_API_KEY`（MiniMax）已配，否则分诊会退化。
3. **前端构建产物上传**：若用 `dist/`，注意字体子集化产物 `public/fonts/*.subset.woff2` 必须一并上传，
   否则线上会回落到 CDN 字体（断网即排版塌方）。
   字体需要重生成时：`python scripts/build-fonts.py`（依赖 fonttools + brotli；原始 ttf 放 `tasks/fonts/raw/`，
   该目录不入库）。
4. **回归验收**（部署完立刻跑）：患者端打卡/症状自查/助手一键同步（此时应显示"已一键同步到医护端预警中心"）、
   家属端代打卡与预警响应、医护端预警中心能看到患者同步过来的预警、患者 360 页出现个人基线带。
5. **（建议）加 `reminders.operator_type`**：家属代为 ack/snooze 提醒时，`reminders` 表没有任何文本/操作人列，
   与患者本人操作无法区分。建议随本次迁移一起加：
   `ALTER TABLE public.reminders ADD COLUMN operator_type text NOT NULL DEFAULT 'patient' CHECK (operator_type IN ('patient','family'));`
   （可选再加 `operator_name text`。前端已在 `medication_logs.reason` 里做「由家属X代填」文本冗余标注，本列用于结构化展示。）

## E. 上线前可选关闭项
- **离线/PWA**（默认在 PROD 启用）：若上线前来不及充分验证，设环境变量 `VITE_OFFLINE_DISABLED=true` 即可整体关闭，
  或用 `localStorage['careloop:offline-disabled']='1'` / 控制台 `__careloopOffline.disable()` 单机关闭。离线入队补传有演练开关
  `localStorage['careloop:offline-dry-run']='1'`（只入队不发送）。

> 回滚：迁移只增不删（无 DROP/DELETE/TRUNCATE），回滚风险低；真出问题只需重跑旧版 Edge Function 代码。
