部署清单（Supabase 后台操作）

本项目前后端直连托管 Supabase，改 supabase/ 下的任何东西都必须按本清单落地才生效。完成一项，划掉一项。

后台：Miaoda 应用后台 → Supabase项目：supabase367321646417096704更新：2026-10-12
🚨
铁律：改完不部署 = 没改。前端连的是线上 Supabase；迁移要在 SQL Editor 执行，Edge Function 要重新部署，两者互不可替。

A. 应用 SQL 迁移（SQL Editor）

1
后台进入 SQL Editor，新建查询
2
按序号粘贴待应用迁移全文如 supabase/migrations/00017_t1_escalate_no_red.sql，点击 Run
3
验证（任选）
  • 00017：SELECT id, level, family_action FROM alerts WHERE source='medication' AND family_action='escalate'; —— 应全部为 yellow
  • 00018：用登录页一键填入演示账号登录，能进即口令对齐成功
4
登记迁移均幂等，重复执行无副作用；执行完在文末待办区划掉
ℹ️
全新库一次性重建：直接粘贴 supabase/ops/full_schema_0001_0018.sql 全文（含 00001–00018 全部迁移），Run 一次即可。

B. 部署 Edge Function

1
后台进入 Edge Functions选择目标函数（如 reminder-scan）
2
用源码全文替换线上代码supabase/functions/<函数名>/index.ts；_shared/ 下的文件如同时改动也要一并同步
3
Deploy等状态变为 Active
4
验证
  • reminder-scan：患者端到点不打卡，30 分钟后消息中心应出现升级消息；同时段两种药只出现一条列出全部药名的提醒
  • triage-symptom：症状自查输入「胸口有点闷」严重度 2 → 黄色；「胸痛」严重度 7 → 红色
⚠️
函数密钥：SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY / SUPABASE_ANON_KEY（平台自动注入）；INTEGRATIONS_API_KEY（MiniMax，Functions → Secrets 手工配置，重建项目时最容易漏）。

C. pg_cron 注册（仅全新库需要）

迁移 00004 已含 careloop-reminder-scan 定时任务注册，依赖 vault 中的 project_url / publishable_key secret。全新库应用 full_schema 后确认：

SELECT * FROM cron.job;   -- 应有一条每分钟执行的任务
