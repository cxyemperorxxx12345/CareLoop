# 需求文档

## 1. 应用概述

### 1.1 应用名称
愈见 · CareLoop（出院患者全周期照护助手）

### 1.2 应用描述
愈见 · CareLoop 是一套连接出院患者、家属照护者与临床医护团队的「医患+家属」三方协同全周期健康照护系统。系统包含宣传介绍落地页、移动端适配的患者端与家属端，以及桌面宽屏适配的医护工作台。通过出院资料智能解析、用药及随访计划生成、三级履约提醒升级响应链、简明红黄绿分诊规则与智能问答助手，实现出院资料结构化录入、家属代打卡与超时协同、医护精准介入与全周期闭环照护。

## 2. 用户与使用场景

### 2.1 目标用户
- 出院患者：查看用药与随访计划、日常打卡、症状自查与智能咨询。
- 家属照护者：查看看护对象康复进度、代患者打卡、接收并响应超时未履约协同任务。
- 临床医护人员：在电脑大屏集中追踪患者康复与依从性、查看患者与家属协同记录、处理分诊及升级预警、维护知识库。

### 2.2 核心使用场景
- 访客在宣传介绍页了解「医患+家属」三方协同照护机制，通过横排快捷按钮进入系统。
- 用户在登录页通过「先选身份、再选演示账号」两步完成快捷登录并进入对应端。
- 患者在手机端查看今日用药与随访计划，完成项目后打勾标记；家属在手机端随时查看进度并在必要时代打卡，右上角可一键退出登录。
- 患者漏服药后触发三级响应链：本人每10分钟接收提醒；30分钟未履约升级至家属端协助；1小时仍未履约升级至医护端介入。
- 患者自查症状命中分诊规则时，系统以柔和低饱和度红/黄/绿标识提示并在医护端产生预警。
- 患者向愈见助手咨询涉及高危症状时，系统在回答下方提供一键同步至医护端与直拨电话快捷卡片。
- 医护人员在桌面端宽屏工作台查阅患者档案、协同记录并处置预警事件。

## 3. 页面结构与功能说明

### 3.1 页面结构

- 愈见 · CareLoop 系统
  - 宣传介绍页（落地页）
  - 登录与身份切换模块
  - 患者端（手机竖屏容器）
    - 今日概览页
    - 出院资料录入与校对页
    - 用药计划与打卡页
    - 随访计划时间轴页
    - 愈见助手对话页
    - 症状自查与分诊页
    - 健康打卡页
    - 消息中心页（含消息详情弹窗）
  - 家属端（手机竖屏容器）
    - 家属协同概览页（含退出登录）
    - 协助代打卡页
    - 升级协同任务页
    - 消息中心页（含消息详情弹窗）
  - 医护端（桌面/Pad 宽屏工作台）
    - 患者管理列表页
    - 患者详情 360 视图页
    - 预警中心页
    - 随访报告管理页
    - 知识库管理页

### 3.2 页面功能说明

#### 3.2.1 响应式布局分端策略
- 患者端与家属端：采用移动端竖屏优先策略，在电脑屏幕上限制容器最大宽度（max-width: 480px）并水平居中，保持手机操作体验。
- 医护端：采用桌面/Pad宽屏网页布局，电脑端采用「左侧固定导航侧边栏 + 右侧自适应宽内容区」，支持Pad及大屏响应式自适应扩展。
- 全局输入控制：全局单行文本输入框与多行文本域统一限制最大输入字数为200字（已有更严格字数限制的字段保持原设定），超长时予以截断或提示。

#### 3.2.2 宣传介绍页
- 顶部导航栏：右上角「登录」与「开始使用」两个操作按钮采用横排并排布局。
- 首屏介绍区（Hero 区）：
  - 全站文案统一采用「医患+家属」三方协同照护表述。
  - Hero 三栏背景色从左至右呈现浅到深的阶梯过渡（患者端浅色、家属端中浅色、医护端中深色但保持柔和不刺眼）。
  - 患者端与家属端两个小手机卡片外形尺寸保持完全等宽高。
- 核心闭环板块排版：
  - 「症状一勾，风险自明」标题下方补充统一风格的简短描述段落，说明基于出院分诊标准、即时评估症状风险与自动预警机制。
  - 支持紧凑高密度排版呈现「患者打卡/漏服 -> 家属协同介入 -> 医护托底闭环」三方协同链路。
- 产品实景展示区：
  - 移动端适配强化：展示的三台设备（患者手机、家属手机、Mac 电脑网页版）在手机竖屏（屏幕宽度小于768px）和宽屏下均必须严格水平居中对齐、完整可见且无横向截断、容器居中无偏移。
  - 素材图片配置：
    - 图片一：https://miaoda-conversation-file.cdn.bcebos.com/user-ezvkyv8gpzi8/app-ezvlp6ds1hqa/20261010/image.jpg（用于患者端与家属端移动界面展示）
    - 图片二：https://miaoda-conversation-file.cdn.bcebos.com/user-ezvkyv8gpzi8/app-ezvlp6ds1hqa/20261010/image-2.jpg（用于医护端Mac电脑网页版全景展示）

#### 3.2.3 登录页
- 快捷体验账号采用两步交互流程：
  - 第一步（身份选择）：提供「患者端」「家属端」「医护端」三个身份选项卡/按钮。
  - 第二步（账号展示）：选定身份后，仅显示当前身份对应的演示账号列表（如患者端显示 guifang，家属端显示 chenming，医护端显示 doctor_wang），点击即可快速填入并登录。
- 支持标准手机号验证码或用户名密码登录。
- 移除原「患者端入口」引导提示文案。

#### 3.2.4 患者端 - 今日概览页与基础配置
- 移除底部常驻免责声明，避免遮挡页面内容与底部导航。
- 展示今日待办用药与随访事项、出院天数与康复进度。
- 提供快速打卡、症状自查、健康指标记录与助手入口。

#### 3.2.5 患者端 - 随访计划时间轴页
- 展示出院后各阶段复诊、检查与康复任务清单。
- 各条目操作采用「复选框打勾」。
- 用户点击打勾后，对应随访条目文字样式自动变为删除线（划掉）且颜色淡化置灰，直观标识已完成状态；取消打勾则恢复正常文字状态。

#### 3.2.6 患者端 - 愈见助手对话页
- 提供基于出院医嘱与公共知识库的健康咨询对话。
- 折叠并隐藏后台推理/思考过程，直接向用户呈现最终回答内容。
- 高危症状联动响应：当 AI 识别到患者描述涉及高危症状或建议就医联系医护时，在回答气泡下方直接展示一键动作卡片：
  - 「一键同步到医护端（生成预警待办）」：点击后直接将当前咨询与高危风险上报至医护工作台预警中心。
  - 「直拨随访科室电话」：点击后唤起系统电话拨号盘呼叫随访科室。

#### 3.2.7 患者端/家属端 - 消息中心页
- 展示用药提醒、协同通知、随访提醒及医护反馈消息。
- 消息详情查看：点击单条消息卡片，弹出模态窗口展示完整消息详情，包含消息标题、消息类型、接收时间、完整正文内容及相关操作动作。
- 单条消息与全量操作：支持单条标记已读；顶部提供「一键全部已读」按钮，支持快速清空所有未读状态。

#### 3.2.8 家属端
- 家属协同概览页右上角设置显式的「退出登录」按钮，支持快速注销并返回登录页。
- 呈现看护对象的今日用药进度、下次用药时间、随访日程及待协同事项。
- 支持家属代患者完成用药打卡，打卡成功后标记「家属代打卡」属性。
- 接收并处理第2级超时升级任务，可选择「已协助服药」「已电话联系」「转医护处理」。

#### 3.2.9 医护端 - 工作台各页面（桌面宽屏）
- 患者管理列表页：展示患者基本信息、当前依从率、绑定家属情况、预警状态，支持多条件筛选与快捷检索。
- 患者详情360视图页：宽屏排版展示患者基础档案、已绑定家属信息、用药履约记录（含自打卡与代打卡标记）、随访时间轴、体征趋势图与预警记录。
- 预警中心页：集中呈现未处理的红/黄等级事件、助手上报的高危事件与第3级超时升级事件，支持录入处置记录并闭环解除。
- 移除底部常驻免责声明。

## 4. 业务规则与核心逻辑

### 4.1 视觉与颜色规范
- 基础色调：主色蜜桃粉霜（#D97A93）、辅助色（#F0B7C3）、背景色（#FDF4F1）、深色（#432C33）。
- 宣传页Hero三栏背景色阶梯过渡规范：左侧患者端浅底色、中间家属端过渡色、右侧医护端中深底色，保证文字对比度与视觉一致性。
- 风险分诊三色规范（采用降饱和度柔和色号）：
  - 红色（高风险/紧急）：低饱和度珊瑚红（#D66868）
  - 黄色（中风险/关注）：低饱和度琥珀橙（#DDA853）
  - 绿色（低风险/正常）：低饱和度鼠尾草绿（#6B9E78）

### 4.2 三级履约提醒升级响应链规则
1. 基础提醒（L0）：到达设定服药时间点，系统向患者端推送基础用药提醒。
2. 第1级（本人频发提醒）：患者在服药时间点漏服后，系统每隔10分钟向患者本人端发送一次打卡提醒。
3. 第2级（家属协同介入）：若漏服持续达30分钟且患者仍无响应，系统自动向家属端推送协同协助任务，提示家属介入督促或代打卡。
4. 第3级（医护介入准备）：若漏服持续达1小时仍未得到任何响应，系统自动将事件升级至医护端预警中心，提示医护人员介入处理。
5. 终止条件：在任一阶段只要完成有效服药打卡，系统立即终止后续提醒与升级流程。

### 4.3 症状分诊规则
1. 红色规则（高风险）：当患者体温超过39℃、高压超过180mmHg，或勾选剧烈胸痛、呼吸困难等危险症状时，判定为红色高风险，提示立即就医并同步上报医护端。
2. 黄色规则（中风险）：当出现轻中度异常体征或持续不适症状时，判定为黄色关注，提示居家对症观察并建议联系医护。
3. 绿色规则（低风险）：症状轻微且体征处于正常区间，判定为绿色正常，给出常规康复生活指导。

### 4.4 消息、输入与打卡状态规则
1. 随访计划打勾完成状态支持撤销（取消勾选后恢复未完成状态并移除划线）。
2. 消息点击后支持弹窗展示完整信息，并自动将该条消息置为已读；支持一键全部标记已读。
3. 系统内所有单行输入与多行文本输入，单次提交字数上限统一限制为200字。

## 5. 异常与边界情况

| 序号 | 异常/边界场景 | 规则与处理逻辑 |
| --- | --- | --- |
| 1 | 患者未绑定家属 | 漏服达30分钟时跳过家属端协同，满1小时后直接升级至第3级医护端预警 |
| 2 | 随访计划误触打勾 | 允许患者再次点击取消打勾，条目恢复正常文字排版并还原未完成状态 |
| 3 | 消息中心全部标记已读时无未读消息 | 操作按钮置灰或点击后静默保持，不触发重复请求 |
| 4 | 演示账号切换身份 | 切换身份选项卡后即时清空已选账号，重新加载对应身份的演示账号列表 |
| 5 | 小屏竖屏访问宣传实景展示区 | 容器及三台设备卡片严格居中垂直排列或缩放自适应展示，禁止横向溢出与内容截断 |
| 6 | 文本输入超出200字 | 输入框阻止继续键入或截断至200字，并给出字数达到上限提示 |

## 6. 验收标准

1. 宣传页 Hero 三栏背景色从左至右呈现浅到深阶梯过渡，患者与家属两个小手机卡片外形尺寸等宽高。
2. 宣传页实景展示区在小屏手机（小于768px）和宽屏下均居中展示、完整可见无横向截断。
3. 宣传页「症状一勾，风险自明」标题下方包含统一风格的简短描述文字。
4. 愈见助手在识别到高危症状或就医建议时，回答下方显示「一键同步到医护端」与「直拨随访科室电话」操作卡片。
5. 患者端与家属端消息中心点击单条消息能正常弹出详情窗口，查看完整标题、类型、时间与正文。
6. 家属端首页右上角提供明确的「退出登录」按钮，点击可注销当前会话。
7. 系统内文本输入框与多行文本域限制最大输入长度不超过200字。
8. 患者端随访计划点击复选框打勾后条目显示删除线与淡化效果，取消打勾可还原。
9. 漏服升级按「每10分钟本人提醒 -> 30分钟家属协助 -> 1小时医护介入」链条准确流转。
10. 医护端、患者端与家属端页面底部均无常驻免责声明。
