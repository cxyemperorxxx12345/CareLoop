# 愈见 CareLoop · 答辩防御一页纸

> 用途：评委质疑 → 标准答案 → 演示时指哪儿。按评审报告建议，**80% 的答辩时间押在「升级链 + 协同 + 处置闭环」这个机制叙事上**，功能清单一句话带过。

## 60 秒演示动线（五步，每步都踩在闭环上）

1. **患者端 · 症状自查**：输入"晨起胸闷"，严重度拖到 **2/10 → 判黄**（规则不滥用红）；再拖到 **7/10 → 判红**，医护端预警中心同步出现同一条（时间戳"1 分钟前"）
2. **医护端 · 预警中心**：该患者多条预警**默认按患者聚合**——组卡直接显示「红色 · 3 条未处理｜用药 ×2 · 分诊 ×1」，可一键切回平铺明细
3. **家属端 · 待协助任务**：点"仍无响应" → 医护端该条变为**黄色「需医护回电」**——红色只留给真正的红旗（演示第 1 步那种）
4. **患者端 · 智能问答**：问"服药后恶心" → **流式作答**，末尾带 `[依据: 个人医嘱]` 引用标注
5. **患者端 · 今日页**：字号一键切「大」——核心用户 68 岁，适老化不是口号是开关

## 六问六答

### Q1「这些功能互联网医院都有，你们的新东西在哪？」
不在功能清单，在**机制**。拍照识别、AI 用药计划、到点提醒确实都是标配——但「漏服升级链 L0→L3（本人→短信→家属→护士站）+ 症状三级分诊直通医护预警 + 家属代打卡带来源标注」三个机制串成的，是**出院过渡期（术后 2-8 周）的处置闭环**：院内有护士、长期慢病有习惯，这段窗口期恰恰没人管。和医院现有随访系统的本质区别：那些系统是"护士打电话+手工记录"，我们把协同动作变成了**患者、家属、护士三方共享的状态机**，每一步留痕、跨端实时可见——演示第 1-3 步就是完整闭环，数据流真实可验。

### Q2「分诊是不是关键词一言堂？误报率多少？」
红旗规则**只兜底、不包办**：命中胸痛/呼吸困难等紧急症状**且**严重度 ≥5（或多个危险症状叠加），或体温 ≥39℃ / 收缩压 ≥180℃ 才判红；**低严重度命中判黄**（24h 联系随访），不直接放行、也不滥用红色。未命中则交给 AI 结合出院诊断、既往史、当前体征综合分级；AI 不可用按严重度兜底。规则全文公开写在患者端「分级规则说明」面板里，评委可当场点开。我们只做分级建议、不做确诊承诺——拿不准时从严。

### Q3「一个护士管 100 个出院患者，每天几百条预警谁看？」
两层降噪。**展示层**：预警中心默认按患者聚合——同一患者的多条预警合并为一张组卡（级别 + 条数 + 来源构成一目了然），先处理人再处理事，随时可切回平铺；**产生层**：同时段多种药漏服只产出一条提醒（列出全部药名），升级链 30 分钟一步、消息写入带 `dedup_key` 唯一索引，同一事件不重复触发。演示第 2 步直接可见。

### Q4「漏服一次他汀也配叫红色预警？」
不配——这正是我们专门修过的点。红色现在**只保留给分诊红旗与危险体征**；漏服升级链最高到黄色「需医护回电」，家属选"仍无响应"也是转黄交还医护。徽章语义因此回归临床：红 = 立即就医，黄 = 电话随访/回电。

### Q5「第 3 周还有多少患者在用？」
不编数字——留存必须上线后验证，这是诚实。但机制上做了三件事对冲"患者自己不打卡"这个最大死因：① **降低门槛**：家属代打卡（记录带来源标注）、稍后提醒（snooze）；② **不制造负罪感**：完成全部用药时的空状态文案是"好好休息"而不是催缴；③ **兜底触达**：患者不打卡，升级链会主动找到家属和护士，数据不会断。依从率趋势在医护端周报可见，低依从患者进入主动随访队列。

### Q6「谁付费？进哪个科室？怎么和医院现有系统对接？」
目标客户：二甲以上医院**心外科 / 骨科等术后科室的随访护士**。付费方：医院随访外包服务或科室运营预算，按在管患者数订阅。对接路径：后端是标准 Postgres（托管 Supabase），HIS 侧只需在出院事件发生时 webhook 推送患者基本信息与医嘱，随访结论回写即可，支持私有化部署。演示环境用托管 Supabase + 演示短信通道（产品内已诚实标注"演示通道"），生产替换真实短信/推送网关。

## 一句话总叙事（收尾用）

> 出院 ≠ 痊愈。愈见 CareLoop 把出院后最危险的 2-8 周，从"患者自己扛"变成「患者—家属—护士」三级协同的闭环：升级链真实可追、分诊规则公开可查、预警按患者合并、红色只留给真正的红旗。
