# 功能需求清单 · 愈见 CareLoop

> 本文档是**给落地 AI 的功能说明书**。每个功能点包含：编号、描述、用户故事、验收标准（Definition of Done）。
> 落地时以「验收标准」为准判断功能是否完成。

---

## 0. 术语表

| 术语 | 含义 |
| --- | --- |
| 患者端 | 面向出院患者的移动优先 Web 界面（`(patient)` 路由组） |
| 医护端 | 面向随访护士/医生的后台界面（`(clinician)` 路由组） |
| 出院小结 | 出院医嘱文档（PDF/图片），本项目核心输入 |
| 随访计划 | 由出院小结生成的一系列待办节点（用药/复诊/换药/注意事项） |
| 提醒 | 到达时间点后向患者推送的通知，需患者确认（ack） |
| 升级策略 | 提醒超时未确认时逐级扩大触达范围（App→短信→家属→护士） |
| 症状分诊 | AI 根据患者描述判断风险等级（green/yellow/red） |
| 预警单 | 由黄色/红色分诊或异常打卡自动生成的、供医护处理的待办 |

**风险等级约定**：`green`（正常，自助建议）、`yellow`（需关注，建议联系医护）、`red`（危险，立即联系医护/急诊）。

---

## 1. 角色与权限

| 角色 | 权限范围 |
| --- | --- |
| `patient` | 管理自己的资料、计划、打卡、问答、症状反馈 |
| `clinician`（护士/医生） | 查看名下患者全部数据、处理预警、生成报告、维护知识库 |
| `admin` | 知识库与系统配置管理 |

**规则**：
- 患者只能访问 `patientId == 自己` 的数据（所有 API 必须做归属校验）。
- 医护只能访问存在负责关系（`PatientClinician`）的患者数据。

## 2. 患者端功能（模块 P）

### P1 出院资料上传与解析 ★核心
- **用户故事**：作为术后患者，我拍下出院小结就能自动得到用药和复诊安排，不用自己抄。
- **功能**：
  - P1.1 支持上传图片（jpg/png）与 PDF，可多页
  - P1.2 上传后异步解析（返回 `documentId`，前端轮询状态）
  - P1.3 AI 结构化抽取字段：`diagnosis`、`medications[]`（药名/剂量/频次/时间点/疗程/备注）、`revisits[]`（日期/科室/目的）、`precautions[]`、`dietAdvice[]`
  - P1.4 结构化结果以**可编辑卡片**展示，患者可修改校对
  - P1.5 确认后一键生成随访计划
- **验收标准**：
  - [ ] 上传 1 张出院小结，60 秒内返回结构化结果
  - [ ] 抽取字段完整度 ≥ 90%（以样例文档为准）
  - [ ] 患者可编辑任一字段并重新确认
  - [ ] 解析失败时有明确错误提示与重试入口

### P2 用药计划与打卡
- **用户故事**：我想清楚知道每天几点吃什么药、吃多少，吃完点一下。
- **功能**：
  - P2.1 按「今日待服 / 全部用药 / 已结束」分组展示
  - P2.2 每个用药项显示：药名、剂量、频次、时间点、剩余疗程
  - P2.3 打卡动作：`已服用` / `稍后提醒` / `跳过`
  - P2.4 统计当日依从率
- **验收标准**：
  - [ ] 打卡后状态即时更新并落库
  - [ ] 「稍后提醒」触发 30 分钟后再提醒
  - [ ] 依从率 = 已服用 / 应服用，实时计算

### P3 随访时间轴
- **用户故事**：我想一眼看到接下来要做的复查和复诊。
- **功能**：P3.1 时间轴展示所有 `FollowUpItem`，按时间排序；P3.2 显示倒计时；P3.3 区分类型（复诊/复查/换药/注意事项）。
- **验收标准**：待办完成后在时间轴标记为已完成并可查看历史。

### P4 智能问答助手 ★核心
- **用户故事**：我有疑问时（"这药能和降压药一起吃吗"）能马上问到答案。
- **功能**：
  - P4.1 对话式界面，支持多轮
  - P4.2 基于患者**个人医嘱知识库**做 RAG，回答须引用其本人计划内容
  - P4.3 越界问题（如诊断/开药）明确拒答并引导联系医护
  - P4.4 回复流式输出；每轮落库为 `Message`
- **验收标准**：
  - [ ] 问「我的降压药什么时候吃」能返回该患者真实医嘱中的时间点
  - [ ] 问「我是不是得了癌症」能明确拒答并建议就医
  - [ ] 对话历史可回看

### P5 症状自查与反馈 ★核心
- **用户故事**：我不舒服时想知道严不严重、要不要去医院。
- **功能**：
  - P5.1 表单选择 + 自由文本描述
  - P5.2 AI 分诊返回：`level`（green/yellow/red）、`advice`、`redFlags[]`、`suggestContactClinician`
  - P5.3 黄色/红色自动生成预警单（P→C 联动，见 C4）
- **验收标准**：
  - [ ] 「伤口轻微发痒」→ green
  - [ ] 「伤口红肿有渗液且发烧 38.5℃」→ red 且生成红色预警
  - [ ] 黄色/红色结果需二次确认后才能提交给医护

### P6 健康打卡
- **功能**：P6.1 记录血压/血糖/体温/体重/血氧；P6.2 症状日记；P6.3 趋势图。
- **验收标准**：数值超出阈值（可配置）时在医护端患者详情中高亮。

### P7 消息中心
- **功能**：P7.1 汇总提醒、系统通知、预警回复；P7.2 未读数角标；P7.3 点击跳转对应页面。

### P8 家属协同（可选，二期）
- **功能**：P8.1 绑定家属手机号；P8.2 家属可代收升级提醒；P8.3 家属只读查看计划。

## 3. 医护端功能（模块 C）

### C1 患者管理
- **功能**：C1.1 患者列表（姓名/疾病/风险等级/依从率/最近随访）；C1.2 搜索与标签筛选；C1.3 仅显示名下患者。
- **验收标准**：列表默认按风险等级降序（红→黄→绿）。

### C2 患者详情
- **功能**：C2.1 基本信息与基础病；C2.2 随访计划进度；C2.3 依从率趋势；C2.4 健康打卡与症状记录；C2.5 **AI 摘要**（自动总结近期状况与风险点）。

### C3 预警中心 ★核心
- **功能**：C3.1 红/黄预警列表（未处理优先）；C3.2 打开可看详情与 AI 建议；C3.3 处理动作：`已联系患者` / `已转诊` / `忽略` + 处理备注；C3.4 处理后状态流转并留痕。
- **验收标准**：
  - [ ] 红色预警在患者提交后 ≤ 5 秒出现在医护端
  - [ ] 处理动作与备注落库到 `Alert`
  - [ ] 未处理预警数在导航栏显示角标

### C4 随访报告生成
- **功能**：C4.1 对某患者一键生成随访问卷式报告（含计划完成情况、依从率、症状事件、AI 总结）；C4.2 支持导出 PDF/打印。
- **验收标准**：报告内容全部来自数据库真实数据，不得虚构。

### C5 知识库管理
- **功能**：C5.1 上传/编辑科普文章与 FAQ；C5.2 自动切片与向量化入 `pgvector`；C5.3 供患者端问答检索。

## 4. AI / 平台服务功能（模块 S）

### S1 文档解析服务
- 输入：文件（图片/PDF）；输出：结构化 JSON（见 P1.3）。
- 要求：使用 LLM 结构化输出（JSON Schema 约束），失败重试；OCR 兜底。

### S2 随访计划生成引擎
- 输入：结构化出院信息 + 当前日期；输出：`FollowUpItem[]`。
- 规则：用药时间点展开为每日多条；复诊按日期生成节点；注意事项作为周期提醒。

### S3 提醒调度与升级引擎 ★核心
- 定时扫描到期 `Reminder` → 推送 → 等待 ack。
- 超时（默认 30 分钟）未 ack → **升级**：`L0 App` → `L1 短信` → `L2 家属` → `L3 护士站`，每级间隔可配置。
- 每级升级记录 `escalationLevel` 与时间，供审计。
- **验收标准**：
  - [ ] 到点准时触发（误差 ≤ 1 分钟）
  - [ ] 未确认时按配置逐级升级并留痕
  - [ ] 患者任意时刻 ack 后终止后续升级

### S4 症状分诊引擎
- 输入：患者描述 + 基础病/近期用药；输出：`level` + `advice` + `redFlags`。
- 要求：规则兜底（关键词命中红旗症状强制 red）+ LLM 判断。

### S5 RAG 检索服务
- 患者个人医嘱 + 机构知识库双路检索，`pgvector` 余弦相似度，返回带出处的片段。

### S6 通知网关
- 抽象通道接口：`inApp` / `sms` / `email` / `push`；demo 阶段 `inApp` 必须实现，其余可打桩（写日志）。

### S7 审计与合规
- 记录关键操作（查看患者数据、处理预警、AI 调用）到 `AuditLog`。

## 5. 需求优先级（MoSCoW）

| 优先级 | 功能 |
| --- | --- |
| **Must（Demo 必须）** | P1 文档解析、P2 用药打卡、P4 智能问答、P5 症状分诊、C3 预警中心、S3 提醒升级 |
| **Should（强烈建议）** | P3 时间轴、P6 健康打卡、C1/C2 患者管理、C4 报告生成、P7 消息中心 |
| **Could（加分项）** | P8 家属协同、C5 知识库、语音输入、趋势图表、周报推送 |
| **Won't（本期不做）** | 在线挂号支付、电子处方、与医院 HIS 对接 |

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 页面首屏 ≤ 2s；AI 接口 P95 ≤ 15s（流式可放宽） |
| 可用性 | 患者端适配移动端（≥360px），字号偏大、操作路径 ≤ 3 步 |
| 安全 | 密码哈希、会话鉴权、接口归属校验、健康数据加密传输 |
| 合规 | 显著免责声明；不得输出明确诊断结论 |
| 可维护 | 服务层与路由解耦，AI 调用统一封装在 `src/lib/ai` |
| 可演示 | 提供种子数据与「一键演示脚本」，3 分钟讲清主线 |

## 7. 关键业务规则汇总

1. 未确认提醒的升级顺序与间隔可配置（默认 30 分钟/级）。
2. 红旗症状关键词命中 → 强制 `red`，不依赖模型。
3. 黄色/红色症状必须经患者二次确认才上报医护（防误触）。
4. 患者只能看到自己的数据；医护只能看到名下患者数据。
5. AI 所有输出仅为建议，界面必须标注「不构成诊断」。
