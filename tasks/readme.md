# 愈见 · CareLoop

> **出院患者全周期照护助手** —— 把一张纸质的出院小结，变成一套会主动提醒、会判断风险、会向医护报警的智能随访系统。
>
> 参赛项目：2026 年 iCAN 大学生创新创业大赛 · AI 无代码智能体挑战赛（医疗健康 / 诊后回访监测 · 用药提醒 · 健康管理追踪）

## 一、项目简介

**愈见（CareLoop）** 是一款面向**慢病与术后康复出院患者**的 AI 全周期照护助手。它覆盖患者从「**出院那一刻**」到「**康复完成**」的整个过程，解决出院后医嘱难懂、依从性差、随访靠人工、异常信号被错过四大痛点。

产品由两端组成：

| 端 | 使用者 | 核心价值 |
| --- | --- | --- |
| **患者端**（移动优先 Web） | 出院患者 / 家属 | 看得懂的用药与随访计划、准时的提醒、随叫随到的问答、异常时有人管 |
| **医护端**（Web 后台） | 随访护士 / 医生 | 一个看板管住一批患者，异常自动上升，随访记录自动生成 |

> 名称释义：**「愈见」谐音「预见」**—— 在患者自己都还没察觉之前，提前预见康复中的风险。
> （`CareLoop` 为项目仓库代号，产品名可替换。）

## 三、目标用户与核心痛点

**目标人群**：糖尿病、高血压、冠心病等慢病患者，以及外科术后康复患者出院后的 4～12 周（延续护理关键窗口期）；用户多为中老年，数字素养有限。

| # | 痛点 | 现状 | 愈见的解法 |
| --- | --- | --- | --- |
| 1 | **医嘱看不懂、记不住** | 纸质出院小结信息密集，患者看不懂剂量与频次 | 拍照上传 → AI 结构化提取 → 用大白话生成可执行计划 |
| 2 | **依从性差、易漏服** | 没人盯着，用药复诊全凭自觉 | 定时主动提醒 + 打卡，未确认自动升级提醒 |
| 3 | **出院即失联** | 随访靠护士电话/微信群人工，无法规模化 | 系统自动随访 + 患者端 7×24 问答 |
| 4 | **异常信号被错过** | 患者分不清「正常恢复」还是「危险信号」 | AI 症状分诊分级 + 红色事件实时推送医护 |

## 四、AI 能力映射（对应竞赛考察点）

| 竞赛考察能力 | 本项目的落地形态 |
| --- | --- |
| **医疗文档处理** | 出院小结/医嘱单 → 多模态解析 → 结构化抽取（诊断、用药、复诊、注意事项）→ 生成个性化随访计划 |
| **患者问答** | 基于患者**个人医嘱知识库**的 RAG 对话助手，回答"这个药饭前吃还是饭后吃"，不越界、不臆造 |
| **任务规划** | 多步症状分诊：理解描述 → 匹配风险规则 → 结合患者基础病 → 给出分级建议或转人工 |
| **工具调用** | 查询患者用药计划 / 写入健康记录 / 创建预警单 / 查询科普知识库 |
| **自主决策** | 提醒未被确认时按 `App → 短信 → 家属 → 护士` 自动**升级提醒策略** |
| **业务流程自动化** | 自动生成结构化随访记录报告；异常事件自动流转至医护端待办 |

## 五、功能总览

> 详细的用户故事与验收标准见 [`docs/requirements.md`](docs/requirements.md)。

### 患者端
- **出院资料承接**：拍照/上传出院小结 → AI 解析 → 校对确认 → 自动生成计划
- **用药计划**：按时间点展示用药清单，打卡（已服用/稍后/跳过）
- **随访时间轴**：复诊、复查、换药等节点与倒计时
- **智能问答**：基于个人医嘱的对话助手（支持语音输入）
- **症状自查**：绿/黄/红三色分级 + 处置建议
- **健康打卡**：血压/血糖/体温/体重 + 症状日记
- **消息中心**：提醒、通知、预警

### 医护端
- **患者管理**：列表、搜索、疾病/风险标签
- **患者详情**：随访计划、依从性、症状记录、AI 摘要
- **预警中心**：红/黄事件待办，处理与备注
- **随访报告**：自动生成、可导出
- **知识库管理**：科普内容/Copilot 语料维护

### AI / 平台服务
- 文档解析服务 · 随访计划生成引擎 · 提醒调度与升级引擎 · 症状分诊引擎 · RAG 检索 · 通知网关 · 审计日志

## 六、技术栈

| 层 | 选型 |
| --- | --- |
| 前端 | Next.js 14（App Router）+ TypeScript + Tailwind CSS + shadcn/ui |
| 状态/请求 | React Server Components + Server Actions / Route Handlers；客户端用 TanStack Query |
| 后端 | Next.js API Routes（单体架构，便于快速落地与演示） |
| 数据库 | PostgreSQL 16+ + Prisma ORM |
| 向量检索 | pgvector（医嘱知识库 RAG） |
| AI | 大语言模型（结构化输出 JSON Schema）+ 多模态/OCR 文档解析 |
| 任务调度 | node-cron（应用内）或 BullMQ + Redis（独立 worker） |
| 认证 | NextAuth（角色：`patient` / `clinician` / `admin`） |
| 部署 | Docker + docker-compose（本地 demo 一键启动） |

## 八、快速开始

```bash
# 1. 安装依赖（Node.js >= 18.18）
pnpm install

# 2. 启动数据库（PostgreSQL + pgvector）
docker compose up -d

# 3. 配置环境变量
cp .env.example .env
# 编辑 .env，填入 DATABASE_URL、模型 API Key 等

# 4. 初始化数据库
pnpm prisma migrate dev --name init
pnpm prisma db seed

# 5. 启动开发服务器
pnpm dev
# 打开 http://localhost:3000
```

**演示账号**（由 `prisma/seed.ts` 生成）：

## 九、核心业务流程（Demo 主线）

```
① 患者拍照上传出院小结
        ↓
② AI 解析 → 结构化展示（诊断/用药/复诊/注意事项）→ 患者校对确认
        ↓
③ 系统生成个性化随访计划（用药时间点 + 复诊节点 + 注意事项）
        ↓
④ 到点自动推送提醒 → 患者打卡「已服用」
        ↓  （超时未确认）
⑤ 自动升级：短信 → 家属 → 护士站
        ↓
⑥ 患者反馈「伤口有点红肿疼」→ AI 分诊 = 黄色/红色
        ↓
⑦ 生成预警单推送医护端 → 护士处理并记录
        ↓
⑧ 系统自动生成随访记录报告，供医护查看
```

## 十、竞赛适配说明

- 本项目**可直接在无代码平台（秒哒 / DuMate）搭建原型**快速展示；本仓库同时提供**代码化实现**，用于深度定制、真实数据存储与本地 demo 演示。

- 若走 **秒哒无代码赛道**：可先可视化搭建患者端主流程（上传→解析→计划→提醒→打卡），再以本仓库为参考补足数据模型与逻辑。

## 十二、合规与安全声明

- 本产品仅提供**健康管理与随访辅助**，**不构成医疗诊断**，所有 AI 建议均需以医生意见为准，界面显著位置标注免责声明。
- 涉及个人健康数据（PHI），需遵循隐私保护原则：最小化采集、传输加密、访问鉴权与操作审计（见 `docs/architecture.md` 安全章节）。
- 演示环境使用**脱敏/虚构数据**，不得上传真实患者信息。
